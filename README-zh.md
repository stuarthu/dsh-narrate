# dsh-narrate

`package.json` 里写的是 0.1.0，**但还没有发布过任何版本**。下面写的是 `main`
上的代码现在能做的事。

一个 [DeepSeek Harness（dsh）](https://github.com/deepseek-ai/DeepSeek-Harness) 插件。

你给它一句想法。它会在四个地方停下来先问你。然后用你自己 `assets` 文件夹里的素材，
出一条带 AI 旁白和硬字幕的视频。

横屏 16:9 给 YouTube 和 B 站，竖屏 9:16 给 TikTok 和 Shorts。

## 状态：整条路已经走通，但还没发布

装之前请先读这一节。

**现在能用的**

- 一句想法出一条成片。每一句都配音、从你自己的文件夹里挑一段画面、裁到这句旁白
  那么长、烧上字幕，最后拼成一个文件——横屏 1920x1080，竖屏 1080x1920。
- **四个停点全都在。** 没有你明确的"继续"，一个都过不去；而且每一个都是工具里的
  硬检查，不是一句说明。
- 素材文件夹入库：递归扫描（跟随软链接，所以放在外置硬盘上的素材也找得到），
  从七个地方读你写的描述和标签，只对指纹变了的素材去问理解那一步。
  一个坏素材不会拖垮整次入库。
- 中文文稿能对上英文的素材信息，靠 agent 给的一个英文查询。稀有的词比样板标签
  值分更多。
- 自带一个不需要 API 密钥的语音引擎，还有一份命令行契约——换引擎只改配置，
  不用改代码。

**还缺的**

- **还没发到 npm。**`npm install dsh-narrate` 现在装不上。要从本地代码装，
  见 [安装](#安装)。
- 理解那一步是一个插入点。插件只告诉 agent 哪几段素材需要看，看得好不好取决于
  agent 和它手上的工具。完全不理解也能挑素材，靠你自己写的描述和标签，只是差一些。
- 横屏素材放进竖屏成片，上下会有很宽的黑边。画面保住了比例、没有被拉伸，这是诚实
  的做法，但和抖音、Shorts 上常见的样子不一样。裁到满屏还没做。
- 什么都不会上传。没有平台账号，不能定时发布，不做封面。这个插件只产出一个文件。

## 隐私：请先读这一节

自带的语音引擎**会把你的旁白文字发到微软的服务器**。

| 什么 | 数据去哪里 | 怎么避免 |
| --- | --- | --- |
| 自带语音引擎（默认） | 你的旁白文字会通过 [`node-edge-tts`](https://www.npmjs.com/package/node-edge-tts) 发给微软 Edge 的在线朗读服务。不需要账号，也不需要 API 密钥。 | 换成本地引擎，见 [换语音引擎](#换语音引擎)。 |
| 你的素材 | 不出你的机器。所有裁剪和编码都是本地 `ffmpeg` 做的。 | 不用做什么。 |
| 你的成片 | 不会上传到任何地方。这个插件不碰你的任何平台账号。 | 不用做什么。 |

自带引擎用的不是微软的官方公开接口，所以它随时可能停止工作。这正是把引擎做成
可替换契约、而不是写死在代码里的原因。

## 这个插件会往你的素材文件夹里写什么

每段素材旁边写一个 `<素材名去掉扩展名>.json`。`bench.mp4` 对应的就是同一个文件夹里的
`bench.json`。

**如果那个名字的文件已经存在，本插件会更新它。** 素材站经常在每段素材旁边附一个元数据
json，那些元数据是有用的：插件会读它的 `title`、`description`、`tags` 和 `search_term`
并用起来。然后把自己的键加进同一个文件——`schema`、`clip`、`fingerprint`、`fromYou`、
`fromMachine`。**不是它创建的键，一个都不动。**

动一个不是它写的文件之前，它会先存一份 `<名字>.json.bak`，只存一次。所以原文永远拿得回来。

有一件事你该知道。如果生成那个 json 的工具以后重写了这个文件，可能会把插件的键一起抹掉。
机器算出来的东西重算一遍就行，不算真的丢。但**你自己**写在那个文件里的内容会没了。想长期
留住的手写内容，放到同名的 `.narrate.txt` 里——见下一节。

素材文件夹里别的地方它都不写，素材本身它永远不改。

### 成片写在哪

一条视频的所有产物都在一个文件夹里，默认是你启动 dsh 的目录下的
`.narrate/<短名>/`：

```
.narrate/clouds/
  job.json            每个阶段都读它写它，各写自己那一节
  audio/S-001.wav     一句一个录音
  preview.wav         停点 4 你要听的那条纯音频
  segments/S-001.mp4  一句一段裁好、烧好字幕的画面
  out/clouds.mp4      成片
```

两次跑之间什么都不删，所以重做只重做变了的部分：你没改过的句子会直接用上次的
录音，不会重配。

## 怎么给素材写描述

下面哪种顺手用哪种，插件会把它们收拢成同一种格式。描述取最明确的那个来源；标签把所有
来源合起来。

| 优先级 | 你在哪写 | 怎么写 |
| --- | --- | --- |
| 1（最高） | 直接跟插件说 | "那段机柜是我自己拍的，版权干净" |
| 2 | 手改 `bench.json` | 改文件里的 `fromYou` |
| 3 | 素材旁边的文本文件 | `bench.mp4.narrate.txt`——第一行是描述，`#` 开头的行是标签，其余进备注 |
| 4 | 表格 | 素材文件夹根目录的 `clips.csv`：文件名、描述、标签（用 `;` 隔开） |
| 5 | 素材旁边本来就有的 json | 下载来源写进去的那些内容 |
| 6 | 文件名 | `服务器机柜-特写_夜景.mp4` 按 `-`、`_`、空格切成标签 |
| 7（最低） | 文件夹名 | `assets/机房/bench.mp4` 得到标签 `机房` |

两件值得知道的事：

- **备注永远不被解析。** 你写"别用在商单里，客户不让露那个机柜编号"，插件一字不动地留着，
  并在写文稿和挑素材时交给模型看。它绝不试图去理解那句话的意思。
- **描述只写一次。** 插件只在它空着的时候填。填过之后那句话就是你的，插件再也不碰它——
  连它自己写的那句也不碰。如果描述不对，把那个字段清空再扫一次，它会重新填。
- **标签只放关键词。** 分辨率、帧率、编码、容器都不会变成标签，`HD`、`High Definition`
  这类词也不会。它们不帮你判断哪段素材配哪句话，而且在真实素材里经常干脆是错的：四个
  素材的标签都写 `1080p` 和 `H.264`，实际里面有一个 640x360、一个 532x300、一个 `vp8`。
- **备注和标签仍然会合并。** 这两样插件记着自己上一次推导出来的值，所以能分清哪句是你
  写的、哪句是它自己上一版的输出。它自己的可以重写，你的会保住，换掉自己的旧输出时会
  说出来。
- **只量时长。** `ffprobe` 会读每段素材的长度，因为"这段够不够盖住这句旁白"要靠它判断，
  裁剪也要靠同一个数。文件的其他信息一概不存。


## 需要什么

- Node.js 22 或更新。测试运行器用到的 glob 需要较新的 Node，而改成靠 shell 展开
  在 Windows 上不成立。
- `PATH` 里有 `ffmpeg` 和 `ffprobe`。用 `ffmpeg -version` 检查。
  如果装在别处，设 `DSH_FFMPEG_PATH` 和 `DSH_FFPROBE_PATH`。
- 至少一个覆盖你写作语言的字体。中文请装 `fonts-noto-cjk` 或任何一个中日韩字体。
  没有字体，每一条字幕都会渲染成空方块。

## 安装

还没发到 npm，所以要从本地代码装：

```sh
git clone https://github.com/stuarthu/dsh-narrate
dsh plugin --profile tui add link:/path/to/dsh-narrate
```

发布之后，`dsh plugin --profile tui add dsh-narrate` 就够了。

装完会注册十个 agent 能调的工具：

| 工具 | 做什么 |
| --- | --- |
| `narrate_start` | 接下你那一句想法，回一组要先问你的问题 |
| `narrate_answer` | 记下你的一个回答 |
| `narrate_script` | 把 agent 写好的文稿编号存下。**问题没答完它会拒绝** |
| `narrate_index` | 扫一遍素材文件夹，说清哪几段还需要理解 |
| `narrate_describe` | 把 agent 对一段素材的理解存下来 |
| `narrate_shotplan` | 给每一句挑一段画面，并列出没有合适素材的句子 |
| `narrate_voice` | 给每一句配音，并拼出停点 4 要听的那条纯音频 |
| `narrate_render` | 裁画面、混旁白、烧字幕、拼成片。**停点 4 没点头它会拒绝** |
| `narrate_approve` | 记下你在某个停点说了"继续" |
| `narrate_status` | 这条视频做到哪了、在等什么、下一步做什么 |

这个分工是刻意的，而且来自 dsh 的形状：**宿主调不到模型。** 所以插件管规则和记忆，
agent 管判断——文稿是它写的，`video_understand` 是它调的，跟你说话也是它。
正因为这样，每一条"不能跳过"都是工具里的硬检查，不是一句 agent 可以无视的说明。

## 它怎么工作

五个阶段，四个停下来等你的地方。

| 停点 | 什么时候 | 你看到什么 | 你做什么 |
| --- | --- | --- | --- |
| 1 | 写文稿之前 | 四个问题：视频多长、给谁看、什么语气、最想让人记住哪一句 | 回答。**回答本身就是那个"继续"**，没有别的要点头的动作 |
| 2 | 文稿写完 | 完整文稿，一行一句，带编号 | 确认或修改 |
| 3 | 生成任何音频之前 | 画面对应表，加上**没有合适素材**的那些句子的清单 | 补素材、改对应表，或者点头继续 |
| 4 | 渲染之前 | 一个纯音频文件：只有旁白，没有画面 | 听语速，确认或重配某几句 |

没有你明确的"继续"，一个停点都过不去。这就是这个插件存在的意义。别的工具一口气
做完，只把结果给你看。

停点 4 是最容易被跳过、又最让人后悔的一个。**只听声音，别看画面**：画面会分散注意
力，而语速错了整条片子都要重做。

每个阶段都是读一个文件、写一个文件，所以没有黑箱，任何一步都能单独重做。中途断了
就调 `narrate_status`，它读一遍文件就知道接在哪里。

### 一次真实的对话长什么样

你说一句，剩下的 agent 做，中间停你四次：

```
你      "帮我做个讲云跑得多快的视频"
agent   narrate_start   → 四个问题，用你的语言问
你      回答                                                      ← 停点 1
agent   narrate_script  → 文稿，一行一句
你      "第三句太长了，删掉"                                       ← 停点 2
agent   narrate_index   → 找到 36 段素材，4 段需要看
        narrate_describe × 4
        narrate_shotplan → 8 句配上了画面，1 句没有
你      "那句删掉"                                                ← 停点 3
agent   narrate_voice   → preview.wav，41 秒
你      听一遍，"稍微快了点，但可以"                                ← 停点 4
agent   narrate_render  → out/clouds.mp4，41 秒，1920x1080
```

### 画面长度跟着音频走

旁白永远保持自然语速。改语速去凑画面长度，正是让旁白听起来假的原因。所以要弯的是
画面：

| 素材的情况 | 会怎么做 |
| --- | --- |
| 比旁白长 | 裁到旁白那么长 |
| 短了 20% 以内 | 放慢。差这么点看不出来 |
| 短了超过 20% | 从选中那一段的起点循环重放 |
| 那个位置根本没有画面 | 当成问题报给你，不会随便拿别的画面填上 |

### 素材什么尺寸、什么帧率都行

每段素材都是**加黑边**放进目标画框，不拉伸；然后在最终分辨率上烧字幕——所以不管
原素材多大，字幕大小都一样。每一段都按同一套参数编码，所以拼接不用重新编码、不掉
画质，而且拼完会把整条片子解码一遍来验。拼坏的时候 ffmpeg 常常并不报错。

## 换语音引擎

语音引擎是**一条命令**，不是一段你必须用 JavaScript 写的插件代码。它读一个文本
文件，写一个音频文件。任何语言都能实现。

命令模板里的占位符：

| 占位符 | 换成什么 |
| --- | --- |
| `%TEXT_FILE%` | 一个 UTF-8 文件的绝对路径，里面是要念的那一句话 |
| `%OUT_FILE%` | 引擎必须把音频写到这个绝对路径 |
| `%LANG%` | 语言代码，例如 `zh` 或 `en` |
| `%VOICE%` | 音色名，原样传给引擎自己解释 |

```yaml
voice:
  command: ["my-tts", "--in", "%TEXT_FILE%", "--out", "%OUT_FILE%", "--lang", "%LANG%"]
  timeoutMs: 60000
```

你的引擎必须做到：

1. 成功时退出码 `0`，并且真的把 `%OUT_FILE%` 写出来。
2. 失败时退出码非 0，原因写到 `stderr`。
3. 只写 `%OUT_FILE%`，绝不修改输入文件。
4. 绝不要交互输入。
5. 输出的音频，`ffprobe` 能读出长度。

文本通过文件传，绝不通过命令行参数传，而且每个参数都作为独立的一项交给进程。
文稿是模型生成的文字，绝不能让它有机会碰到 shell。

完整契约（包括每一个错误名）在
[`docs/crew/api/voice-engine.md`](docs/crew/api/voice-engine.md)。

## 已有的同类项目

有好几个项目今天就能把整件事做完。它们都不会停下来先问你，而这正是这个插件唯一
要做的事。

- [OpenCut-AI](https://github.com/Ekaanth/OpenCut-AI) —— 用视觉相似度把文稿每一段
  匹配到你自己的素材库，全本地跑。
- [OpenMontage](https://github.com/Open-Montage/OpenMontage) —— agent 驱动的视频
  制作系统，很多流水线和工具。
- [NarratoAI](https://github.com/linyqh/NarratoAI) —— 影视解说专用，写稿到配音
  到字幕一条龙。
- [MoneyPrinterTurbo](https://github.com/harry0703/MoneyPrinterTurbo) —— 一个主题
  或关键词出短视频，主要用网络素材库。

这个插件的原则是复用而不是重写：[`dsh-ffmpeg`](https://github.com/STARDUSTLC666/dsh-ffmpeg)
做视频处理，[`dsh-video-understand`](https://github.com/ilps2/dsh-video-understand)
把素材在本地变成文字，`node-edge-tts` 当默认语音。
