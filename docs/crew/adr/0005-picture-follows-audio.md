# ADR 0005：画面时长服从音频，不是反过来

**决定。** 每句话的画面长度，由该句旁白音频的真实长度决定。

**衡量过的选项。**

1. 先配音，量出真实时长，再把画面裁成那个长度（选了这个）。
2. 先定每句画面多长，再调语速让旁白刚好念完。
3. 两边都不动，中间垫静音或黑帧对齐。

**为什么选它。**

选项 2 听起来更整齐，但代价落在观众耳朵上。为了塞进固定时长，语速会一句快一句慢，听着很假。而且中文和英文的字数与时长关系差别很大，同一套画面时长换个语言就全乱。

选项 3 会让视频里出现观众能察觉的停顿或黑帧。

选项 1 的声音永远是自然语速，这是"稿子驱动"视频最重要的品质——观众是来听的。

**代价。** 画面时长在配音跑完之前是未知的，所以渲染不能提前开始。这也是本项目最危险的边界（见 `hld.md` 第 6 节）：一个数字要在两个模块之间传得一模一样，差 0.05 秒就会越往后越歪。`T-01` 就是为了先撞一次这个风险。

另一个代价是素材可能不够长。这一条在 PRD 的 `Q-6` 里还没定，需要用户选一个默认动作。
