# ADR 0003：语音引擎是一条命令，不是一段代码

**决定。** 语音引擎通过命令行接入：命令读一个文本文件，写一个音频文件。

**衡量过的选项。**

1. 命令行契约（选了这个）。
2. 代码插件：用户写一个 JavaScript 模块，实现我们的接口。
3. 只支持我们内置的几个引擎，写死在代码里。

**为什么选它。**

产品目标是"任何创作者都能用"。选项 2 要求用户会写 JavaScript，而大多数创作者不会——这一条就废掉了"可插拔"的意义。选项 3 每加一个引擎都要我们改代码发新版，用户等不起。

选项 1 让任何语言写的引擎都能接：Python 脚本、云服务的命令行客户端、甚至一个 shell 脚本。中文语音这个领域变化很快，好引擎经常换，用户自己就能跟上。

还有一个现实原因。自带的免费引擎用的不是官方公开接口，随时可能坏（见 PRD 的 `R-4`）。做成契约，坏了换一条命令就行，产品代码零改动。

**代价。** 每句话多启动一个进程，大约几十毫秒，一条 8 分钟视频总共多几秒。另外命令行传参有安全风险——文稿是模型生成的内容，拼进 shell 字符串就等于让它能执行命令。所以契约里写死两条：文本必须通过文件传，参数必须逐项传给进程，绝不拼 shell 字符串。
