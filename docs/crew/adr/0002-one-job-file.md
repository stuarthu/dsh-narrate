# ADR 0002：一个工作文件，每节只有一个写入者

**决定。** 所有阶段共用一个 `job.json`。每个阶段独占一节，只写自己那一节。

**衡量过的选项。**

1. 一个文件，分节独占（选了这个）。
2. 每个阶段一个文件，例如 `script.json`、`shotplan.json`、`voice.json`。
3. 一个文件，谁都能写任何地方。

**为什么选它。**

选项 2 要写四份格式约定，两个不能说话的工程师要多读四份文件。而这四份约定里，重复的部分很多（句子编号怎么写、时间用什么单位、路径是绝对还是相对）。约定越多，两侧读出不同意思的机会越多。

选项 3 是最省事的写法，也是最容易坏的。两个阶段写同一个地方，谁最后写谁赢，而且没有任何报错。这种问题在成片里才看得出来，排查要很久。

选项 1 保住了选项 2 的隔离（一节一个写入者），又只有一份格式约定。写别人的节在运行时直接抛错，不等到成片。

**代价。** 一个文件比四个文件大，人读起来要翻。而且改格式版本要所有阶段一起认。这个代价用一件事换回来了：用户只需要看一个文件就知道整条视频做到哪一步了。
