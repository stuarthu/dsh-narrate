## 验收检查逐条

30 条里 M6 直接负责 `A-8`、`A-9`、`A-10`、`A-12`、`A-16`、`A-17`、`A-18`，
加上 `T-08` 的 `A-5`。全部有可跑的检查守着，见 `docs/crew/qa/T-09/`。

评审时改了三条检查，理由都写进 `prd.md` 了：

| 检查 | 改了什么 | 为什么 |
| --- | --- | --- |
| `A-12` | `.srt` 改成 `.ass` | `force_style` 里的像素不是像素，实测竖屏字幕跑到画面顶部 |
| `A-16` | 去掉"单次上限 20 段"这个理由 | 那是 `dsh-ffmpeg` 工具的上限，我们用的 concat 分离器没有上限 |
| `A-26` | 补上"要存进工作文件并回显" | 光算出来不算交付 |

风险 `R-2`（20 段上限）**判定为不存在**，换成了一个真实的风险：拷流拼接会
"成功"地拼出坏片子。对策是参数一致才拷流，拼完量时长**并且**完整解码一遍。

## 评审发现的问题（都已修）

| 问题 | 怎么发现的 |
| --- | --- |
| 竖屏字幕画在画面顶部 | 在真画面上量了一次。单元测试全绿 |
| 扫描交出来的形状和挑素材那一侧对不上，36 段素材一句都配不上 | 真素材端到端跑了一次 |
| `assign.js` 写 `clipPath`，契约和渲染都是 `assetPath` | 同上 |
| 拷流拼接退出码 0 但成片坏了 | 故意拿参数不一致的片段试了一次 |
| 只有一段素材时所有分数都是 0，一句都配不上 | 写挂载测试时碰到 |
| `narrate_status` 自己一套阶段判断，只认到停点 2 | 接剩下四个工具时发现 |
| `A-26`、`A-27` 算出来了但 agent 看不到 | 这次评审逐条对检查时发现 |
| **`narrate_shotplan` 根本没守停点 2** | M6 验收逐个试停点时发现。别的工具靠底层的 `assertReady` 守住，只有它漏了——停点 2 能被整个绕掉 |
| **插件的引导有死循环** | M6 验收照指示走时卡住。`index` 那一步的完成条件是"对应表存在"，而没完成时它说"调 narrate_index"，于是永远到不了 `narrate_shotplan` |
| 我自己的验收脚本会空转当成通过 | 主用例失败后 `made` 是空的，空循环里断言一次都不跑，后面五条全绿。比失败糟得多 |
| README 说 `npm install dsh-narrate`，而包没发布 | `T-10` 逐条核对 README 的说法 |

共同点：**十个里有九个是"跑一次真东西"或"逐条核对"发现的，不是想出来的。**

最后那三个尤其值得记：`narrate_shotplan` 没守门和引导死循环，都是"每一步单独测都对、
连起来走不通"，只有**照插件自己的指示走一遍**才看得见。所以那份验收脚本刻意不把顺序
写死——它测的就是引导本身。

## 没做的事

- **模型的判断没验。** DeepSeek 账户报 `QUOTA: Insufficient Balance`，真会话起不来。
  dsh 确实带着插件启动了、也走到了调模型那一步，这证明十个 schema 挂载时不抛异常。

  `qa/M6/run.sh` 把能在 dsh 之外验的都验了：机械上走得通、引导完整没断点、四个停点
  逐个都绕不过去、两种比例都出得来，用的是真素材和真配音。**它验不了的**是 agent
  的判断——文稿写得好不好、英文查询会不会写成拍摄手法、会不会真的把停点念给用户听。
  那三样在脚本里是人手替身。

  所以 `A-15`（工具出现在 dsh 会话的工具列表里）算部分验证：`--dump-config` 能看到
  插件行，装出来的包也挂载出十个工具，但没在会话里看过工具列表。
- **横屏素材做竖屏成片，上下有很宽的黑边。** 保比例不拉伸是诚实的，但不是抖音和
  Shorts 上常见的样子。裁到满屏没做，这是一个产品选择，等一个新的变更请求。
- **还没发布。** 没有 npm 包，没有 tag。发布流程写在 `CLAUDE.md` 的 Releases 一节。
