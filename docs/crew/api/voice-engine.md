# 边界契约：语音引擎（`voice` → 外部引擎）

| 项目 | 值 |

| 版本 2 改了什么 | 第 6 条跟着 `flow-stages.md` 版本 2 改：静音完全裁掉，不是裁到 0.15 秒 |
| 拥有者 | `voice` |
| 涉及任务 | `T-01`（调用侧和自带默认引擎，走通骨架） |

## 风格

**命令行调用。** `voice` 启动一个外部命令，命令读一个文本文件，写一个音频文件。

## 为什么是命令行，不是代码插件

命令行契约让**任何语言写的引擎**都能接进来：Python 脚本、Node 脚本、一个云服务的命令行客户端、甚至一个 shell 脚本。用户想换引擎，不用读我们的代码，也不用写 JavaScript。

代价：启动一个进程比调一个函数慢，一句话大约多几十毫秒。一条 8 分钟的视频约 100 句，总共多几秒。可以接受。

## 命令怎么拼

配置里给一个参数模板。`voice` 把模板里的占位符换成真值，然后**把每个参数当成独立的一项传给进程**。

| 占位符 | 换成什么 |
| --- | --- |
| `%TEXT_FILE%` | 要念的文本文件的绝对路径，UTF-8，无 BOM，一句话一个文件 |
| `%OUT_FILE%` | 音频输出的绝对路径，`voice` 决定 |
| `%LANG%` | 语言代码，例如 `zh`、`en` |
| `%VOICE%` | 音色名，由配置给，引擎自己解释 |

配置形状（举例，不是规定引擎）：

```yaml
voice:
  command: ["my-tts", "--in", "%TEXT_FILE%", "--out", "%OUT_FILE%", "--lang", "%LANG%"]
  timeoutMs: 60000
```

## 安全规则：不准拼 shell 字符串

**`voice` 绝对不准把命令拼成一个字符串交给 shell 执行。** 每个参数必须作为独立的一项传给进程。

理由：要念的文本来自模型生成的文稿，是程序没有选择过的内容。拼进 shell 字符串就等于让文稿内容能执行命令。加引号不是解决办法，参数列表才是。

文本也**必须**通过文件传，不准通过命令行参数传。两个理由：一句话可能很长，超过命令行长度上限；而且文件传递彻底绕开了引号和转义。

## 调用侧（`voice`）必须做的事

1. 建好 `%OUT_FILE%` 的上层目录，再启动进程。
2. 文本写成一个独立文件，UTF-8，不带 BOM，不带多余的换行。
3. 每个参数独立传，不经过 shell。
4. 超时按配置的 `timeoutMs`（默认 60000 毫秒）。超时要**连子进程一起杀掉**，不能留下孤儿进程。
5. 进程结束后，按下面的检查表逐条判断，任何一条不过就报对应的错误名。
6. **返回的 `audioPath` 一定以 `.wav` 结尾。** 引擎给的可能是 `.mp3`，那份原始文件留着当中间产物，但裁完静音写出的是 PCM WAV 数据，所以最终文件名必须是 `.wav`。扩展名和内容对不上，任何相信扩展名的程序都会坏。
7. 通过之后，把音频前后静音**完全裁掉**（阈值 `-50 dB`，峰值检测），再用 `ffprobe` 量时长。顺序不能反：先裁再量。这一条的理由和实测精度在 `flow-stages.md` 的"最要紧的一节"里。

## 引擎侧必须保证的事

一个引擎要能接进来，必须做到这五条：

1. 成功时**退出码 0**，并且 `%OUT_FILE%` 那个文件真的写出来了。
2. 失败时退出码非 0，错误说明写到 `stderr`。
3. 只写 `%OUT_FILE%` 这一个文件。不准往别处写，不准改输入文件。
4. **不准要交互输入。** 不问密码，不等回车。
5. 输出的音频必须是 `ffprobe` 能读出时长的格式。推荐 `wav` 或 `mp3`。

## 错误名字

| 错误名 | 什么时候 |
| --- | --- |
| `E_ENGINE_NOT_CONFIGURED` | 配置里没有 `command`、模板里缺 `%TEXT_FILE%` 或 `%OUT_FILE%`、或者命令根本启动不起来（可执行文件不存在、没有执行权限） |
| `E_ENGINE_FAILED` | 退出码非 0。错误消息里必须带上 `stderr` 的前几行 |
| `E_ENGINE_TIMEOUT` | 超过 `timeoutMs` 还没结束 |
| `E_ENGINE_NO_OUTPUT` | 退出码 0，但 `%OUT_FILE%` 不存在或是 0 字节 |
| `E_ENGINE_BAD_AUDIO` | 文件在，但 `ffprobe` 读不出时长 |

## 自带的默认引擎

插件自带一个免费引擎，不需要 API key，装完就能出声（对应验收检查 `A-13`）。它按上面五条规则实现，和别的引擎一视同仁——**没有任何走后门的特殊路径**。

它用的不是官方公开接口，可能随时坏（`R-4`）。这正是这条边界要做成契约的原因：坏了换一个命令就行，产品代码零改动（`A-14`）。

## 好不好用

写一个新引擎的人最容易犯的错，是成功了却忘了写文件，或者失败了还返回 0。`E_ENGINE_NO_OUTPUT` 就是为这个准的：调用侧不相信退出码，只相信文件。

## 契约测试

| 侧 | 测试证明什么 |
| --- | --- |
| `voice` 侧（调用者） | 用一个手写的假引擎脚本当桩。四个用例：正常写文件退出 0、退出 0 但不写文件、退出 1 并往 `stderr` 写字、睡到超时。测试证明四种情况分别得到成功、`E_ENGINE_NO_OUTPUT`、`E_ENGINE_FAILED`（消息含 `stderr` 内容）、`E_ENGINE_TIMEOUT`。另有一个用例：文本内容里带 `; rm -rf /` 这类字符，测试证明它被当成普通文字念出来，没有任何命令被执行。**必须跑在假引擎桩上，不准调真引擎** |
| 引擎侧（自带默认引擎） | 给它一个文本文件和一个输出路径。测试证明：退出码 0，输出文件存在且 `ffprobe` 能读出大于 0 的时长 |

两个测试都必须先失败再通过。

**没有网络时怎么办。** 自带的默认引擎要联网。没有网络的机器上，引擎侧测试必须**出声跳过**：打印一行说明为什么跳过，并标记为 skipped，不算失败。`voice` 侧的四个用例全部跑在假引擎桩上，永远不需要网络。这和 `dsh-crew` 自己的 `verify-mount.mjs` 在缺少某个包时出声跳过的做法一致。

## 改这个文件的规矩

契约在任何一侧的任务开工之后就**冻结**。工程师发现它错了，报给 PM，PM 交给架构师。**只有架构师能改这个文件。** 改完 PM 通知两侧重读新版本。

必须改的时候，优先**只加不改**：加一个新占位符、或一个新的可选配置项。这四种改法会弄坏另一侧，做了就要说清楚，而且两侧都要重跑：改占位符名字、删占位符、把可选配置变必填、改一个错误名的含义。
