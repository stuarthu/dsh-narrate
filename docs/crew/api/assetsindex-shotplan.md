# 边界契约：clip 描述文件（`assets-index` → `shotplan`）

| 项目 | 值 |
| --- | --- |
| 版本 | 8 |
| 拥有者 | `assets-index` |
| 涉及任务 | `T-02`（读写和两节分工）、`T-03`（人类输入源翻译）、`T-04`（接视频理解）、`T-06` 和 `T-07`（`shotplan` 读它） |

**版本 8 改了什么**（加法改动）：`fromYou` 多两个字段，都是真实数据撞出来的。

`origin` —— 逐字段记下**是谁给的**，以及**上一次推导出来的值**。为什么需要：原来判断"这是手改"的办法是"推导不出来"，但**我们自己上一个版本的输出也推导不出来**。真实数据撞出过这个 bug——读取器改成用 `title` 之后，上一次存下的长 `description` 被当成手改，永远压着新的推导结果。所以要做标准的三方合并：存着的值等于上次推导的基准，就是我们的旧输出，放心覆盖；不等于，说明用户在我们写完之后改过，那才是手改。

`replaced` —— 覆盖了自己的旧输出时列出来。用户有权知道那句话去哪了，而不是发现它不声不响没了。

同时改了第七个读取器：拿 `title` 当描述（archive.org 的 `description` 常常是推广文案，而 `title` 短、可靠、总在说画面），他们那段长 `description` 放进 `notes`，`search_term` 加进标签——那是这类文件里最有用的一个词。

**版本 7 改了什么**（**破坏性改动**，两侧都要重读）：

真实素材文件夹第一次测试就把版本 6 打穿了。从 archive.org 下载的素材，每个旁边自带一个同名 `.json`，里面是 `title`、`description`、`tags`。版本 6 的做法是报 `E_FOREIGN_JSON` 并跳过，结果**整个文件夹一个素材都入不了库**，而那些元数据恰恰是我们最想要的东西。

所以规则反过来：

1. **已经有同名 `.json` 就用它，不再拒绝。** 我们只**增加**自己的键（`schema`、`clip`、`fingerprint`、`fromYou`、`fromMachine`），别人的键一个都不动、不删、不改。
2. **第一次动一个不是我们写的文件之前，先备份一份 `<名字>.json.bak`。** 只备份一次。写错了能拿回来。
3. `E_FOREIGN_JSON` 只留给**没法合并**的情况：文件是合法 JSON 但不是一个对象（是数组、字符串、数字）。那时候没有地方放我们的键。
4. 新增第七个读取器：同名 `.json` 里别人写的 `title` / `description` / `tags`。优先级排在同名文本和表格之后、文件名和文件夹之前——那是下载来源给的，比文件名可信，但不如你自己特意写的。
5. 扩展名清单补齐（`.ogv`、`.ogg`、`.3gp`、`.mts`、`.m2ts` 等），并且**认不出来的媒体文件要报出来**，不能静默跳过。真实素材来源五花八门。

**已知代价**：如果下载工具以后重写了那个 `.json`，它可能把我们的键一起抹掉。`fromMachine` 丢了能重算，但用户**写在那个文件里**的内容会真的没了。所以文档要建议：想长期留住的手写内容放同名 `.narrate.txt`。

**版本 6 改了什么**（加法改动）：补上两个错误名 `E_ASSETS_ROOT_UNREADABLE` 和 `E_SCAN_INTERNAL`；写明软链接怎么处理。

**版本 5 改了什么**（加法改动，另一侧不用重跑）：补上 `E_SOURCE_UNREADABLE`；写明翻译这一步会读现有的 `<clip>.json` 来认出手改，所以别人的文件或坏文件会让翻译也停下；写明表格可以只解析一次传进来。

**版本 4 改了什么**（`T-02` 和 `T-03` 都还没开工，所以这次改动代价为零）：

1. 从"一个大索引文件"改成**一个 clip 一个 JSON**。一个文件写坏只坏一个素材，不会让整个素材库不可用。
2. 文件里把**你给的**和**机器算的**分成两节。机器可以整块重写自己那节，永远碰不到你那节。
3. 因此删掉了 `describedBy` 和 `stale` 那一整套"绝不能盖掉人写的"规则表。现在"人写的赢"是结构上的事实，不是一条要记住的规则。
4. 描述的单位从**整个文件**改成**时间段**。整段 10 分钟的素材里有几十个画面，一条描述代表不了；而画面搜索返回的本来就是时间点。
5. 加了人类输入源的清单和它们的优先级，加了自由文本 `notes`，加了指向画面向量缓存的字段。

## 风格

**文件交接。** 一个 clip 一个 JSON，放在**这个 clip 旁边**，文件名是 clip 去掉扩展名后加 `.json`：

```
assets/机房/bench.mp4
assets/机房/bench.json      <- 这一个
```

放在旁边而不是集中在一个隐藏目录里，是为了让描述**跟着素材走**：你单独把一段素材拷给别人，描述一起过去；你把整个文件夹搬到别的硬盘，描述也不会掉队。

## 格式

JSON，UTF-8，缩进 2 空格。时间单位是**秒**，浮点数，3 位小数。

```json
{
  "schema": "dsh-narrate/clip@1",
  "clip": "bench.mp4",
  "fingerprint": "size:104857600|mtime:1755600000",

  "fromYou": {
    "description": "深圳某机房，我自己拍的，版权干净",
    "tags": ["机房", "服务器", "自拍素材"],
    "notes": "别用在商单视频里，客户不让露那个机柜编号",
    "segments": [
      { "startSec": 12.4, "endSec": 31.0, "description": "这一段是我最满意的镜头" }
    ],
    "sources": ["folder:机房", "sidecar:bench.mp4.narrate.txt", "chat:2026-08-20"],
    "origin": {
      "description": "sidecar:bench.mp4.narrate.txt",
      "notes": "sidecar:bench.mp4.narrate.txt",
      "derived": { "description": "…上一次推导出来的值，当下次的合并基准…", "notes": "…", "tags": ["机房"] }
    }
  },

  "fromMachine": {
    "durationSec": 63.200,
    "segments": [
      { "startSec": 0.0,  "endSec": 12.4, "description": "远景，机柜走廊，蓝色光", "tags": ["远景"], "confidence": "low" },
      { "startSec": 12.4, "endSec": 31.0, "description": "特写，有人在插网线",     "tags": ["特写"], "confidence": "high" }
    ],
    "visualSearchDir": "/home/you/.cache/narrate/avis_cache/8f2a1c9b04/tiny_clip/bench_avis",
    "engine": "video-understand-l0"
  }
}
```

## 两节的分工

**这是本契约最重要的一条。**

| 节 | 谁写 | 什么时候被重写 |
| --- | --- | --- |
| `schema` `clip` `fingerprint` | `assets-index` | 每次入库 |
| `fromYou` | `assets-index`，但**只从人类输入源翻译而来**（见下一节） | 只在人类输入源变了的时候 |
| `fromMachine` | `assets-index` | 指纹变了就**整块重写** |

理解素材那一步（调视频理解）**绝对不许碰 `fromYou`**。这样机器可以随时把 `fromMachine` 全部重算，你写的东西永远不会丢。

`shotplan` **只读**这两节，一个字都不能写。

## 人类输入源，和它们的优先级

你可以用任何你顺手的方式给描述和标签。插件负责把它翻译成上面那个格式。"任何方式"的真实含义是**一组读取器，可以一个个加**：

| 优先级 | 来源 | 怎么写 | 落到哪 |
| --- | --- | --- | --- |
| 1（最高） | 跟插件说 | "那段机柜是深圳拍的，版权干净" | `fromYou`，`sources` 记 `chat:<日期>` |
| 2 | 你直接改 `bench.json` 的 `fromYou` | 手改这个文件 | 原样保留 |
| 3 | 同名文本 `bench.mp4.narrate.txt` | 第一行描述，之后每行 `#标签`，其余行进 `notes` | `sources` 记 `sidecar:<文件名>` |
| 4 | 表格 `assets/clips.csv` | 三列：文件名、描述、标签（分号隔开） | `sources` 记 `csv:clips.csv` |
| 5 | 同名 `.json` 里别人写的键 | 拿 `title` 当描述，长 `description` 进 `notes`，`search_term` 和 `tags` 进标签 | `sources` 记 `clipjson:<文件名>` |
| 6 | 文件名 | `服务器机柜-特写.mp4` 按 `-`、`_`、空格切词 | 只进 `tags` |
| 7（最低） | 文件夹名 | `assets/机房/bench.mp4` → 标签 `机房` | 只进 `tags` |

规则：

- **越明确的赢。** 两个来源给了不同的 `description`，取优先级数字小的那个。
- **`tags` 是合并，不是替换。** 所有来源的标签取并集，去重。标签越多越好找。
- **翻译必须可重跑且结果一样。** 同样的输入源重读一遍，`fromYou` 必须一字不差。否则你会发现自己写的描述莫名变了。
- **翻译要读现有的 `<clip>.json`**，因为手改只存在于那里。所以别人的文件（`E_FOREIGN_JSON`）或坏文件（`E_CLIP_JSON_UNREADABLE`）会让翻译这一步也停下，这是对的：读不懂现有内容就不该覆盖它。
- **表格允许只解析一次。** 一个文件夹几百个素材，每个都重解析一遍 `clips.csv` 是白做的功。调用方可以把解析好的表格传进来，翻译逐个素材时复用。
- **分清"用户改的"和"我们上一版的输出"，靠三方合并。** 每次都把这一轮推导出来的值记进 `origin.derived` 当基准。存着的值等于基准就是我们的旧输出，放心覆盖；不等于就是用户改的，粘住。没有基准的老文件按"我们的旧输出"处理，但必须列进 `replaced` 说出来。
- **`notes` 不解析。** 插件不去理解它的意思，只在写文稿和挑素材时把它交给模型看。没有这个字段，"翻译成插件格式"就等于把你最要紧的那句话删掉。
- **软链接要跟进去。** 素材放在外置硬盘、用软链接接进 `assets` 是常见做法，所以判断类型要用跟随软链接的方式，不能只看目录项本身。同时要记住已经走过的真实路径，防止 `assets/loop -> assets` 这种环把扫描卡死。
- **理解失败不代表要扔掉你写的东西。** 那一条素材的 `fromYou` 照样存下来，`fromMachine` 留空，下次入库自动重试。
- **`fromYou` 没变就不重写。** 几百个素材每次扫描都重写一遍是白做的写盘。
- 中文文件名**不分词**。`服务器机柜-特写` 能切出三个词，`服务器机柜特写` 只算一个。这是真实限制，不要指望它。

## 两个必须响亮报错的地方

**1. 名字撞车。** `bench.mp4` 和 `bench.mov` 在同一个文件夹里，会撞成同一个 `bench.json`。报 `E_STEM_COLLISION`，两个文件名都列出来，然后**停下**。绝不许把两段不同素材的描述混进一个文件。

**2. 没法合并的 JSON。** 同名 `.json` 已经存在是**正常情况**，不是错误：用它，只增加我们自己的键，别人的键一个都不动。但如果那个文件是合法 JSON 却**不是一个对象**（是数组、字符串、数字），就没有地方放我们的键——报 `E_FOREIGN_JSON`，跳过这个素材，一个字节都不写。

动一个不是我们写的文件之前，**先存一份 `<名字>.json.bak`**，只存一次。别人的文件被我们弄坏，是最不可原谅的一种 bug，所以要留一条退路。

## 数据归谁，读的人可以相信什么

- **`assets-index` 拥有这些文件。`shotplan` 只读。**
- 描述文件在，**不保证 clip 现在还在磁盘上**。`shotplan` 挑中一段素材后必须自己确认文件存在，不存在就报 `E_ASSET_MISSING`。
- **`fingerprint` 只用大小和修改时间，不含路径**，所以你把整个 `assets` 搬到别的硬盘，`fromMachine` 依然有效，不用重算。
- **但 `visualSearchDir` 会失效。** 画面向量缓存由 `dsh-video-understand` 拥有，它的缓存键**含路径**，所以搬完就得重算。找不到这个目录时，`shotplan` 必须当成"没有画面搜索可用"、退回文字匹配，**不是报错**。
- `confidence` 是 `low` 的时间段，描述可能很空。原因是本地视频理解靠语音识别、场景切换和运动，一段**没有人说话**的画面，它几乎说不出内容。`shotplan` 必须把 `low` 当较弱的证据，用了要在缺素材报告里说明。

## `shotplan` 怎么挑：三层漏斗

读的人按这个顺序筛，从便宜到贵：

| 层 | 做什么 | 需要什么 |
| --- | --- | --- |
| 1. 时长 | 从候选起点算，剩余长度盖不住这句旁白的，直接排除 | 只读这些 JSON |
| 2. 文字 | 用 `description`、`tags`、`notes` 的词重叠留下候选 | 只读这些 JSON |
| 3. 画面 | 把这句话翻成**一句英文画面描述**，交给画面搜索定到第几秒 | `visualSearchDir` 存在，且装了画面向量那一层 |

第 3 层**可选**。没有它就只跑前两层，质量差一些，靠停点 3 由用户兜。

为什么第 3 层要先翻成英文：画面向量用的文字编码器是英文语料训练的，中文查询匹配质量差很多。

三层之上还有一步**分配**。100 句话、20 段素材，每段平均要用 5 次。如果每句独立取"最像的一段"，很多句会挑到同一段，成片会反复闪同一个画面。所以要统一分配：用过的降权，相邻两句不来回切。这是分配问题，不是查找问题。

## 错误名字

| 错误名 | 什么时候 |
| --- | --- |
| `E_STEM_COLLISION` | 同一个文件夹里两个 clip 去掉扩展名后同名 |
| `E_FOREIGN_JSON` | 目标 JSON 是合法 JSON 但不是一个对象，没法把我们的键加进去 |
| `E_CLIP_JSON_UNREADABLE` | 是我们的文件，但不是合法 JSON。不准覆盖它，报错跳过这一个素材 |
| `E_CLIP_SCHEMA_UNKNOWN` | `schema` 不是本模块认识的版本 |
| `E_ASSET_UNREADABLE` | clip 文件存在但读不出时长 |
| `E_ASSET_MISSING` | 描述文件里写的 clip 在磁盘上不存在 |
| `E_UNDERSTAND_FAILED` | 视频理解失败。这一条跳过并记下，**不中断整次入库** |
| `E_ASSETS_ROOT_UNREADABLE` | 素材文件夹本身读不到。整次入库停下 |
| `E_UNKNOWN_MEDIA` | 文件看着像媒体文件但扩展名不认识。报出来让用户知道，不静默跳过 |
| `E_BACKUP_FAILED` | 备份 `<名字>.json.bak` 失败。不写原文件，报错跳过 |
| `E_SCAN_INTERNAL` | 出了一个没有错误码的意外错误。**必须用这个码，不能借用 `E_UNDERSTAND_FAILED`**，否则程序 bug 会被当成"这个视频不好理解"藏起来 |
| `E_SOURCE_CONFLICT` | 两个同优先级的来源给了不同的 `description`。列出两边，让用户决定 |
| `E_SOURCE_UNREADABLE` | 人类输入源存在但读不出来（权限不对、编码坏了）。不猜内容，报错停下 |

## 好不好用

读的人最容易犯的错，是把 `confidence: "low"` 的时间段当成和 `high` 一样可信，配出一堆错画面。防住它的办法：读接口不返回一个大列表，而是分两个——`highConfidence()` 和 `lowConfidence()`。想用弱证据，必须显式去要。

写的人最容易犯的错，是重算 `fromMachine` 时顺手把整个文件覆盖掉，连 `fromYou` 一起没了。防住它的办法：写接口只接受 `fromMachine` 这一节，函数签名里根本没有写整个文件的入口。

## 契约测试

| 侧 | 测试证明什么 |
| --- | --- |
| `assets-index` 侧 | 建 3 个假 clip，入库。在第 2 个的 `fromYou.description` 手写一句话，再碰一下第 2 个文件的修改时间，然后重新入库。测试证明：第 1、3 个没被重新理解（调用次数 0），第 2 个的 `fromMachine` 重算了，**而它的 `fromYou.description` 一字未变**。另外三个用例：同文件夹放 `a.mp4` 和 `a.mov` 报 `E_STEM_COLLISION`；放一个没有 `schema` 标记的 `b.json` 报 `E_FOREIGN_JSON` 且那个文件字节数不变；同样的输入源连跑两次，`fromYou` 完全相同（可重跑） |
| `shotplan` 侧 | 手写两个 clip 描述文件的桩，一个有 `high` 时间段、一个只有 `low`。测试证明：能配上 `high` 的句子用了 `high`；只能配上 `low` 的句子用了 `low` 且报告里带"把握不高"；时长盖不住的候选在第 1 层就被排除；`visualSearchDir` 指向一个不存在的目录时**退回文字匹配而不是报错**。**必须跑在手写桩上，不准调真的 `assets-index`** |

两侧的测试都必须先失败再通过。

## 改这个文件的规矩

契约在任何一侧的任务开工之后就**冻结**。工程师发现它错了，报给 PM，PM 交给架构师。**只有架构师能改这个文件。** 改完 PM 通知两侧重读新版本。

必须改的时候，优先**只加不改**：加一个新字段、且不设为必填。这四种改法会弄坏另一侧，做了就要说清楚，而且两侧都要重跑：改字段名、删字段、把可选字段变必填、改一个错误名的含义。
