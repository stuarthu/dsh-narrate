# CRD 0001：把 dsh 挂载提到现在做

| 项目 | 值 |
| --- | --- |
| 谁要求 | 用户 |
| 日期 | 2026-08-20 |
| 决定 | **accepted**，用户决定。理由：那三个注入点建立在一个错误假设上，先做 `M4` 会让 `T-06` 和 `T-07` 继续压在错的接缝形状上。现在挂一次，等于先过最危险的那条边界 |

## 要什么

现在就把三个注入点接上：`understand`（理解素材）、`compose`（写文稿）、
`extraQuestions`（额外问题）。

## 为什么

`M1` 到 `M3` 做完之后，三个注入点全都还没接线，`T-10`（dsh 挂载）悄悄变成了
"让一切变真"的那个任务，而它排在最后。所以在此之前，用户拿不到任何能真的用起来
的东西。

## 查出来的事实（这一条比变更本身更重要）

**宿主不能调模型。**

dsh 插件的形状是 `apply(ctx, config)` 加 `ctx.tools.register(定义)`（见
`dsh-ffmpeg/lib/index.js`）。工具的 `execute` 在**宿主进程**里跑，把返回值交给
agent。宿主这一侧没有任何调模型的入口。

所以这三个注入点**不可能**做成"宿主调模型"的函数。那个假设是错的。真实形状是
反过来的：**插件出工具，agent 当编排者。**

| 原来的假设 | 真实的形状 |
| --- | --- |
| 宿主调 `compose(想法, 回答)` 拿回句子 | 插件出一个工具，**agent 把自己写好的句子传进来**，插件校验、编号、存盘 |
| 宿主调 `understand(素材)` 拿回描述 | 插件出一个工具说"这几段需要理解"，agent 去调 `video_understand`，再把结果交回来 |
| 宿主调 `extraQuestions(想法)` 拿回问题 | 插件把四个核心问题交给 agent，agent 自己决定要不要补问 |

已经写好的代码不作废：那些注入点仍然是接缝，只是填进去的东西由 agent 送来，
而不是宿主自己去取。`scanAssets({ understand })` 这样的签名照旧可用。

| `T-10` | 大部分内容被提前的这个新任务吃掉，剩下 README 更新 |

## 代价

1. **`T-08` 要重新设计。** 这是最大的一项。好消息是它还没开工，所以没有代码要扔。
2. **现在挂载，还不能出片。** `M4`（画面对应表）没做，所以挂上之后你能真的用的是：
   素材入库、反问、写文稿。从想法到成片这条整链还差 `M4`。
3. **多一个里程碑停点。** 原来的 `M4` 和 `M5` 之间要插一个。
4. 挂载本身有真实的未知：`ctx.tools.register` 的参数形状我只从 `dsh-ffmpeg` 的
   编译产物里读到，没写过。第一次可能要试几轮。

## 好处

1. 三个注入点变成真的，不再是占位。
2. 你能在 dsh 里**真的走一遍停点 1 和停点 2**——给一句想法，被反问，拿到文稿。
3. 素材入库能拿到**真的 AI 描述**，`M2` 那个只做到一半的目标补上。
4. 架构假设的错误现在就暴露了，而不是等到 `M5` 才发现——那时候 `T-08` 已经按错的
   形状写完了。
