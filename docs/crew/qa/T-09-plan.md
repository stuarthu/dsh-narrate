# T-09 的 QA 计划

从验收检查写，不是从代码写。`T-09` 交付 `A-8`、`A-9`、`A-16`、`A-17`、`A-18`。

| 用例 | 对应验收检查 | 怎么判通过 |
| --- | --- | --- |
| 1 | `A-8` | 配完音，每句一个音频文件，文件名里带得回句子编号，`ffprobe` 读得出时长 |
| 2 | `A-9` | 停点 4 的纯音频能解码播放，时长约等于各句之和，句数对得上 |
| 3 | `A-16` | 65 段拼成一条，`ffprobe` 读出的时长约等于各段之和，完整解码无坏帧 |
| 4 | `A-17` | 竖屏出片，`ffprobe` 报 1080x1920；字幕不超出左右边（量最左和最右两条竖条，应是黑边） |
| 5 | `A-17` 追加 | 字幕在画面**下部**，上半干净。竖屏曾经把字幕画在顶部而测试全绿，所以这一条要单独量 |
| 6 | `A-18` | 一篇英文文稿跑一遍：旁白是英文（要联网，没网就出声地跳过），字幕文件里是英文 |
| 7 | `Q-6` | 素材比旁白短：缺口小的放慢、缺口大的循环，两种成片时长都等于旁白时长 |
| 8 | `A-12` | 五样中间产物都在：索引、文稿、对应表、逐句音频、`.ass` 字幕。**原来这一条要的是 `.srt`**，改成 `.ass` 的理由写在 `prd.md` 的 `A-12` 里 |
| 9 | `A-10` | 三句各配不同长度的音频，每一句的画面时长和**它自己那句**音频相差不超过 0.2 秒。给三句一样长的音频验不出这件事 |

用例 6 要联网。没网时**出声地跳过**，不算失败——红灯必须意味着代码错了。
