# M6 里程碑验收计划（在 dsh 之外）

`prd.md` 给 M6 定的验收方法是「在 dsh 里真做一条视频」。DeepSeek 账户余额不足，
真会话起不来，所以这份计划在 dsh 之外尽可能地做到同一件事。

## 核心办法：顺序由插件说，不由脚本说

脚本每一轮只做一件事：调 `narrate_status`，读它给的 `tool`，调那个工具。
脚本**不知道** `narrate_script` 之后该干什么——插件知道。

这样验的东西正是真会话里 agent 会走的那条路：**只照插件的指示走，能不能走到成片。**
走不到就说明引导有断点。第一次跑就是这样抓到「素材入库那一步是死循环」的。

## 三处人手替身，都在日志里标明

真会话里 agent 贡献三样东西，dsh 之外没有模型，所以由人手提供并标注：

| 替身 | 真会话里由谁做 |
| --- | --- |
| 四个反问的回答 | 用户自己答 |
| 文稿的字 | agent 写 |
| 素材理解、每句的英文查询 | agent 调 `video_understand`、按工具说明写查询 |

**所以这份验收不证明模型的判断是对的。** 它证明的是：机械上走得通、插件的引导完整、
四个停点绕不过去、两种比例都出得来。

## 检查项

| 用例 | 判通过的标准 |
| --- | --- |
| 1 | 横屏：一句想法走到成片，全程由插件带路，四个停点都点过头 |
| 2 | 竖屏：同上 |
| 3 | 两条成片都能完整解码，画面和声音都在 |
| 4 | 横屏 1920x1080，竖屏 1080x1920 |
| 5 | 每一句的画面时长跟着**它自己那句**旁白，差不超过 0.2 秒 |
| 6 | 成片总长约等于各句旁白之和 |
| 7 | 字幕烧在画面下部、上半干净，且一段只有一条字幕、内容和文稿一致 |
| 8 | 中间产物齐全：索引、文稿、对应表、逐句音频、`.ass` |
| 9 | 四个停点逐个试：不点头就往下走，每一个都要报错 |

用真素材（默认 `~/assets`，可用 `NARRATE_ASSETS` 指到别处）。没有素材就**出声跳过全部**。
语音引擎能联网就用自带的真引擎，不能就用本地假引擎并说明。

## 每一条检查都不许空转

前面失败时 `made` 是空的，`for (const x of Object.entries({}))` 是空循环，断言一次都不跑
——**检查会空转当成通过**。所以后面每一条先调 `bothMade()` 确认两条片子都在。
第一次跑就踩到了这个：两条主用例失败，后面五条却全绿。
