# dsh-narrate 产品需求文档（PRD）

| 项目 | 值 |
| --- | --- |
| 版本 | 2 |
| 日期 | 2026-08-20 |
| 文档语言 | 中文 |
| 状态 | 等你确认 |
| 版本 2 改了什么 | 从"只服务 B 站"改成跨平台：加了竖屏、字幕随比例变、语音接口不锁语言 |

术语：**素材** = 你放到 `assets` 文件夹里的视频片段。**旁白** = AI 语音朗读你的文稿。**索引** = 一个文件，记录每段素材里有什么。**停点** = 插件停下来等你回答的地方。**横屏** = 16:9，宽的。**竖屏** = 9:16，高的。

---

## 1. 一句话

`dsh-narrate` 是一个 DeepSeek Harness（dsh）插件。你给它一句想法，它带你走四个停点，最后用你自己 `assets` 文件夹里的素材，出一条带 AI 旁白和硬字幕的 `mp4`。横屏和竖屏都能出。

## 2. 问题

做一条有旁白的视频，人要花很多小时。最费时间的四件事：

1. 一句想法离一篇能念的文稿很远，写稿最慢。
2. 素材有几十上百个，记不住哪个片段里有什么。
3. 对时间轴是体力活。旁白多长，画面就要铺多长。
4. 字幕要一句一句敲。

现有工具能自动做完这些，但它们不停下来问你。它们做完你才看到结果，不满意就整条重做。

## 3. 用户

| 谁 | 说明 |
| --- | --- |
| 主用户 | 做"稿子驱动"视频的创作者。旁白是主线，画面跟着句子走 |
| 平台 | 不锁平台。B 站、YouTube 用横屏；TikTok、YouTube Shorts、小红书用竖屏 |
| 不是用户 | 做混剪 / 卡点视频的人。那是音乐驱动，另一个引擎 |

## 4. 核心决定：只写编排层

这一版**不重写**素材理解、视频处理和语音合成。这三样已经有现成的东西，重写是浪费。

| 层 | 用什么 | 谁写 |
| --- | --- | --- |
| 素材理解 | `dsh-video-understand`（L0 本地：语音识别 + 场景 + 运动 → 文字信息层） | 别人 |
| 视频处理 | `dsh-ffmpeg`（`probe` / `cut` / `concat` / `encode` / `subtitle` / `extract`） | 别人 |
| 语音合成 | 可插拔接口，自带一个免费默认引擎（不要 API key） | 接口我们写，引擎用别人的 |
| **编排** | 四个停点的流程、画面对应表、缺素材报告、索引管理 | **我们写** |

**为什么模型不直接看图。** dsh 的 DeepSeek 通道会拒绝图片内容（`dsh-llm-deepseek/lib/index.js:41`），DeepSeek 公开 API 到 2026 年 7 月仍是纯文本。所以素材必须先在本地变成文字，模型只读文字。

## 5. 要做什么

| 编号 | 功能 |
| --- | --- |
| F-1 | 扫 `assets` 文件夹，为每段素材建一条索引记录 |
| F-2 | 索引只算一次。素材没变就不重算 |
| F-3 | 索引可以手改。手改的内容在重扫后保留 |
| F-4 | 拿到一句想法后，先反问你几个问题，问完才写文稿 |
| F-5 | 把想法展开成完整文稿，按句子编号 |
| F-6 | 为每句话挑一段素材，生成画面对应表 |
| F-7 | 挑不到合适素材的句子，明确列出来报给你 |
| F-8 | 为每句话生成一个音频文件，一句一个 |
| F-9 | 把画面裁到该句音频的长度 |
| F-10 | 把字幕烧进画面 |
| F-11 | 拼成一条 `mp4` |
| F-12 | 保留全部中间产物：索引、文稿、对应表、逐句音频、`.srt` |
| F-13 | 语音引擎可以换。换引擎只改配置，不改代码 |
| F-14 | 装成 dsh 插件，用 `dsh plugin add` 安装 |
| F-15 | 画面比例可选：横屏用 `bilibili-1080p`，竖屏用 `vertical-1080p`（1080x1920） |
| F-16 | 字幕样式跟着比例走。竖屏字号更大、每行字更少、位置更高 |
| F-17 | 语音接口不锁语言。中文、英文都能用，只要引擎支持那个语言 |

## 6. 四个停点

| 停点 | 在哪一步 | 插件给你看什么 | 你做什么 |
| --- | --- | --- | --- |
| 停点 1 | 写文稿之前 | 至少 3 个问题：视频多长、给谁看、语气、最想让人记住哪句 | 回答 |
| 停点 2 | 文稿写完 | 完整文稿，按句子编号 | 确认或改 |
| 停点 3 | 配音之前 | 画面对应表，加上"这几句没有合适素材"的清单 | 补素材、改对应表，或点头继续 |
| 停点 4 | 渲染之前 | 一个纯音频文件，只有旁白没有画面 | 听语速和断句，确认或重配某几句 |

四个停点都必须等你回答。没有明确的"继续"，插件不往下走。

## 7. 验收检查

每一条都能由没写代码的人验证。

| 编号 | 检查 |
| --- | --- |
| A-1 | 放 3 个视频文件进 `assets`，跑入库，索引里每个文件都有一条记录，含文字描述 |
| A-2 | 不加新文件再跑一次入库，日志显示 0 次重新理解，索引内容不变 |
| A-3 | 手改索引里一条描述，再跑入库，改动还在 |
| A-4 | 给一句想法，插件提出至少 3 个问题，且在收到回答前不产生文稿文件 |
| A-5 | 文稿生成后插件停住。不回答"继续"，不生成对应表 |
| A-6 | 画面对应表每行包含：句子编号、素材文件名、起秒、止秒、字幕文本 |
| A-7 | 故意放一句索引里配不上的内容，停点 3 的报告里明确列出该句编号和"缺素材" |
| A-8 | 配音后每句一个音频文件，文件名能对回句子编号 |
| A-9 | 停点 4 给出的纯音频文件能用 `ffplay` 播放，内容与文稿一致 |
| A-10 | 成片能用 `ffplay` 播放。每句的画面时长与该句音频时长相差不超过 0.2 秒 |
| A-11 | 成片里字幕烧进画面，文字与该句文稿一致，中文不出现方块 |
| A-12 | 中间产物齐全：索引、文稿、对应表、逐句音频、`.srt`，五样都在 |
| A-13 | 不设置任何新 API key，只有 `DEEPSEEK_API_KEY`，默认语音引擎能出声 |
| A-14 | 换成另一个语音引擎只改配置文件，产品代码零改动 |
| A-15 | `dsh plugin add` 之后，插件的工具出现在 dsh 会话的工具列表里 |
| A-16 | 一条 60 段以上的视频能拼成功（`dsh-ffmpeg` 的 `concat` 单次上限是 20 段） |
| A-17 | 用竖屏模式出一条片，`ffprobe` 报告分辨率是 1080x1920，且字幕没有超出画面左右边 |
| A-18 | 用一篇英文文稿跑一遍，默认语音引擎出英文旁白，字幕是英文 |

## 8. 不做

| 不做什么 | 为什么 |
| --- | --- |
| 混剪 / 卡点：BPM 检测、自动卡点 | 音乐驱动是另一个引擎，不是加个开关 |
| 剪映草稿工程 | 格式无文档、随版本变、跨平台路径不同，当地基太危险 |
| 背景音乐（BGM） | 第一版不做，见 Q-2 |
| 转场特效、封面、片头片尾 | 交给剪辑软件 |
| 为每种语言调优 | 只保证接口不锁语言。每种语言的断句规则、语速、字幕换行不逐一调 |
| 自动下载素材 | 素材由你自己放进 `assets` |
| 上传到任何平台 | 不碰你的账号 |
| 数字人、对口型、声音克隆 | 超出"稿子驱动"的范围 |
| 判断素材版权 | 插件只提醒，不判断，见 R-7 |

## 9. 里程碑

`M1` 是概念验证，也是走通骨架：最薄但真的能跑通的一条路。

| 编号 | 目标（你能看到什么） | 你怎么试 |
| --- | --- | --- |
| M1 | 一句话变成一个能播的 5 秒 `mp4`：有旁白、有画面、有硬字幕，三者对得上 | 用 `ffplay` 播放它 |
| M2 | 你能看到一份素材清单：`assets` 里每段素材有什么，写在一个可手改的索引文件里 | 打开索引文件读 |
| M3 | 你给一句想法，插件反问你，然后给你一篇完整文稿等你审 | 走一遍停点 1 和停点 2 |
| M4 | 文稿变成画面对应表，缺素材的句子被明确报出来 | 走一遍停点 3 |
| M5 | 一句想法跑到成片，四个停点全部串起来，横屏和竖屏都能出，装成 dsh 插件 | 在 dsh 里真做一条视频 |

**M1 为什么是这条路。** 最危险的边界是"配音"和"成片"之间：画面要裁多长，取决于旁白音频的**真实**长度，而这个长度只有配音跑完才知道。而且我核实发现 `dsh-ffmpeg` 缺两个工具（见 R-1）。这两件事必须在第一个任务就撞一次，那时改还便宜。

## 10. 风险

| 编号 | 风险 | 怎么应对 |
| --- | --- | --- |
| R-1 | `dsh-ffmpeg` 没有"把旁白混进视频"的工具，也没有"把素材拉长到指定时长"的工具 | M1 必须先解决：自己直接调 `ffmpeg`，或者给 `dsh-ffmpeg` 提 PR |
| R-2 | `dsh-ffmpeg` 的 `concat` 单次最多 20 段。短视频不受影响，长视频远超这个数 | 分批拼接，见 A-16 |
| R-3 | 没有人说话的 B-roll 素材，L0 几乎说不出画面内容 | 见 Q-5，三条路都有代价 |
| R-4 | 免费语音引擎用的不是官方公开接口，可能随时坏 | 接口可插拔，坏了换一个，见 F-13 |
| R-5 | 硬字幕改一个字要重渲画面 | 音频和对应表都留着，重渲是一条命令，只花 CPU |
| R-6 | 依赖三个别人的插件，别人升版可能把我们弄坏 | 在 `package.json` 里写死版本下限，并在 CI 里跑真实端到端测试 |
| R-7 | 下载的素材用在自己视频里有版权风险 | 插件在停点 3 提醒一次，不做判断 |
| R-8 | 竖屏一行放不下多少字。中文约 12 到 15 字，英文更少 | F-16 按比例换字幕规则；文稿那一步就要按比例控制句子长度 |

## 11. 还没定的问题

| 编号 | 问题 | 我的提议 |
| --- | --- | --- |
| Q-1 | 包名和仓库名 | `dsh-narrate`。中立、不锁平台，且说清了产品是什么：旁白驱动的视频。npm 上空着 |
| Q-2 | 要不要背景音乐 | 第一版不做。加 BGM 要处理音量压制，会拖慢 M5 |
| Q-3 | 默认比例和帧率 | 默认横屏 1080p / 30fps。竖屏用参数切换，不是默认 |
| Q-4 | 你现在做一条视频要多久 | 需要你给一个数字，用来衡量这个插件到底省了多少时间 |
| Q-5 | 没声音的 B-roll 怎么索引 | 三条路：装 2 GB 本地层（`torch`/`CLIP`/`YOLO`）、加一个小米 MiMo 的 key 用 L1、或先接受 L0 的弱描述并靠停点 3 兜住 |
| Q-6 | 你点头继续之后，缺素材的句子默认怎么处理 | 你说过"延续上一段素材"。但上一段会用完，剩下的时长要选：循环重放、最后一帧定格、还是放慢拉长 |
| Q-7 | 短视频要不要"快速模式" | 一条 30 秒的 TikTok 走四个停点可能太重。建议 M5 做完再看，不提前设计 |
